# AI Evals: Final Project

My final project for Product School’s **AI Evals certification**, applying evaluation strategy, failure analysis, and release gates to **Ascend IQ**, a B2B market intelligence assistant.

**My recommendation: HOLD** the enterprise rollout until broader pricing tests meet the release criteria. Catching one critical failure is a useful signal, but it does not establish reliability.

## Deliverables at a glance

| Module | Deliverables |
|---|---|
| [M1 · Evaluation strategy](01-evaluation-strategy/) | User promise, trust metrics, and trade-offs |
| [M2 · Failure discovery](02-failure-discovery/) | Scored audit and prioritized failure taxonomy |
| [M3 · Eval suites](03-eval-suites/) | Three evaluators, results, and pricing eval spec |
| [M4 · Eval gates](04-eval-gates/) | Release gates, thresholds, and mitigation |
| [M5 · Scale](05-scale/) | Coverage gaps and evaluation budget |
| [M6 · Culture](06-culture/) | Ship-or-hold recommendation and ownership |

## The feature in one sentence

Ascend IQ helps enterprise leaders make decisions using source-backed market intelligence; incorrect pricing or unsupported claims can damage trust and put $50K+ annual subscriptions at risk.

## Per-module loop

I defined the user promise, audited failures, tested evaluators, set release gates, assessed coverage and cost, and used the evidence to make a release recommendation.
